# 音乐网络播放（2026-10-25）

音乐打开时先查既有账号、路径和文件版本对应的完整音频缓存。存在完整缓存时沿用 FD 播放；未缓存时向 NAS 取得当前登录会话的临时下载描述符，通过 media.createMediaSourceWithUrl(url, headers) 和 AVPlayer.setMediaSource 播放，使用系统缓冲，不再调用整首 ensureCachedFile。

系统播放器按需请求音频内容。preferredBufferDuration 设为 8 秒，关闭播放器离线缓存；这不是额外持久下载队列。用户明确点击下载仍沿用原有传输功能。地址与鉴权头只在播放器生命周期内保留，关闭后清空，不写入接续快照或日志。

接续继续携带文件位置、文件树/目录索引、进度和播放状态。接收端使用自己的 NAS 登录态重新取得地址，不传整首歌曲、源端 FD、缓存路径或临时令牌。准备后先 seek 到目标进度，再按原播放状态决定是否播放。

已验证：

- audio-streaming-regression 运行实际 AudioPlaybackManager 和实际页面 openAudioPlayer 方法，覆盖带头网络源、缓存路径、接收端重新解析地址、97531ms 暂停状态恢复、切歌/Back/账号变化/初始化取消、异常与释放。
- 接续、媒体返回、后台保护回归通过；调试 HAP 构建成功。
- 平板 PCE-W30 打开 Music/1 中 107.4 MB 未缓存 FLAC，日志确认 network 源，UI 已播放到 0:04；没有应用整首下载或 staging 文件。快照采集本身有耗时，7.92 秒是点击到第二次采集结束，不是起播延迟。
- 暂停后进度稳定；点击约 60% 跳到 159801ms，恢复播放正常；Home 后回前台进度增加 5624ms；切下一首、系统控制中心封面、关闭返回及首划通过。
- 此轮没有实际双端流转：手机在线但锁屏。接续传输与页面适配由正式回归覆盖，原生网络播放和 seek 在平板验证。

歌曲标签收尾已完成：经用户同意，文字与封面共用 AudioArtworkReader 的 Range 窗口、预算、账号检查和解析工具。支持 ID3v2.2/2.3/2.4、FLAC Vorbis Comment 与 M4A/iTunes 标签，读取标题、歌手、专辑；完整本地缓存仍沿用系统元数据提取。未知或损坏标签保留文件名，不影响播放。

- 保留单次 3 MiB / 16 个请求 / 8 秒检查期限 / 单请求 3 秒超时的上限；文字字段最多读取 16 KiB，显示最多 512 字。递归 atom 深度和总数也有限制。
- 已有封面但没有文字缓存时跳过 APIC/PICTURE/covr 大块；从文件列表新提取封面时一次解析两者。范围请求正在共享时，一个关闭的页面不会中断新页面仍需要的同一查询；各消费者提交前都校验当前曲目与账号。切换账号会停止后续范围请求并丢弃旧结果。
- 仅保留最近 128 首的文字元数据，按账号和文件版本隔离；不在内存长期保留原始封面字节。查询失败后可以重试，不把网络失败写成永久无标签。
- 正式 audio-tags-regression 覆盖真实编码的微型合成 MP3/FLAC/M4A、中文/日文/UTF-16、专辑歌手备用、跳过大图片与 mdat、损坏边界和模糊输入。夹具约 22 KiB，测试不依赖 temp 文件或运行时 ffmpeg。
- audio-presentation-regression 运行实际仓库与页面方法，覆盖一次范围查询共用、已有封面走文字读取、128 条 LRU、版本/账号隔离、快速关开、网络恢复、本地复用、过期结果丢弃以及向系统发布正确标签。
- 平板的未缓存 107.4 MB FLAC 正常播放，页面显示正确标题与歌手；系统 AVSession 同时包含正确专辑，控制中心与页面一致。原始核对数据保存在忽略的 temp/audio-tags/，不提交用户歌曲信息。

格式与编码依据：[ID3v2.4 结构](https://id3.org/id3v2.4.0-structure)、[FLAC 格式说明](https://xiph.org/flac/format.html)，以及 DevEcoCLI《如何实现字符串编解码》的 TextDecoder 用法。
