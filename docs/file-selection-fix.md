# 多选点击与区间拖选修复 — 2026-10-02

已构建并安装到 `192.168.0.142:44631`。用户实际操作后确认“点击和拖选都正常”。

## 问题与修改

- 原勾选框在 Index 的 Builder 中读取根级 `selectedPaths`，每次选择变化会使这些依赖失效；成员查询使用数组 `indexOf`。现在使用独立的 `FileSelectionState` 与指示器组件，只更新发生变化的勾选框或瀑布流轮廓。选择数据独立于 `FileEntry.previewRevision` 和图片管线。
- 选择集合改为 Set；按当前目录筛选所选条目的结果每次变化只计算一次，供底栏操作复用。底栏节点 ID 固定，不再随数量持续改写。隔空传送注册在提交新选择后重新评估。
- 命中表原先累积旧目录、旧表面和已回收格子的矩形。现在按目录和表面隔离，回收时移除，并校验索引对应的当前 path。只对约 2vp 的格子间隙取最近格，避免落在缝隙时终点停留在前一格。
- 原本在长按成功时就翻转起点，序列手势未进入 Pan 时又缺少整体取消收尾。现在长按只冻结快照，Pan 成功后才应用范围；开始、更新、结束均处理落点，组合手势取消也收尾。普通滑动继续由滚动容器处理。

## 拖选规则

以本次手势前的选择快照为基准，**首节点和末节点都包含在范围中**。范围内每项各自反转，范围外保持原状态。回拖使范围缩小时，退出范围的项目恢复快照；同一终点的重复事件不再写入状态。只更新旧、新范围两端变化的部分。

Grid、List 使用当前文件顺序；瀑布流使用实际展示的 `waterfallEntries` 顺序，避免图片筛选后的索引对应到错误文件。

## 拖选靠近边缘自动滚动

List、Grid、WaterFlow 的长按拖选接入自动滚动。长按只建立快照，Pan 成功后才启动；有效文件区域的上下各 56vp 为触发带，避开固定顶栏和底部操作栏。越靠近边缘越快，速度范围为 72～720vp/s；离开触发带、松手、取消、页面隐藏或到达内容边界时停止。

滚动使用 16ms 定时步进，单次累计时间最多 32ms，避免 JS 延迟后突然跳动。滚动期间通过 Scroller 的实时索引重新命中停留手指下的项目，仍按手势前快照对包含首尾节点的区间执行 XOR。Root Touch 持续保存同一手指的窗口坐标，避免移动或回收格子的 Pan 坐标与原始触摸坐标交替覆盖；原始 Touch 只跟踪坐标，不参与普通滚动的手势竞争。

自动滚动每个小步产生的 ScrollStop 合并到拖选结束后处理，避免逐帧启动预览补刷和位图清理。List 的起始占位节点在 Scroller 索引换算时扣除，瀑布流保持自身展示顺序。
