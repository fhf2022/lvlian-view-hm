# 大图旋转后的网格返回定位

基于 `91ee467`，修复平板竖屏打开大图、转横屏返回后，目标图片可能落在可见范围外却没有进入最小滚动准备的问题。

## 原因与边界

普通网格采用单图 Overlay 返回，原来始终跳过最小滚动准备，目标未挂载或不可见就淡出。横竖屏改变网格尺寸和可见行数，因此单纯获取最新目标矩形仍不足以把目标带回屏幕内。

本次增加两个私有数字，分别记录页面尺寸变化版本和打开图片时的版本。利用现有页面 `onAreaChange` 更新版本，没有新增逐格监听、`@State`、后台轮询或缓存。

- 未改变布局时保持原有返回快速路径，不滚动、不增加渲染帧等待。
- 布局改变时先恢复窗口方向策略，再等待两个连续版本稳定的渲染帧，最多等待 8 帧。以返回时实际可见区判断目标；已经完整可见就不移动。
- 需要定位时复用 `prepareMediaReturnSource` 和 `scrollItemIntoContentBand`，先按文件身份找到当前图，再做最小滚动。网格使用缩略图的真实矩形，排除第一行顶部留白和文件夹名称，不按整个 GridItem 居中。
- 目标尚未挂载时先用原生 `ScrollAlign.AUTO` 挂载，再按顶栏下沿、底部悬浮栏上沿精确校正。上下边界与列表、音频共用辅助方法；沿用最多 8 帧的挂载/校正循环。
- 返回动画只使用当前已经显示的图片资源，不触发原图解码。挂载 Overlay 时若再次发生尺寸变化则淡出，拒绝飞向旧矩形。动画开始后不补滚动、不留延迟滚动定时器。

## 验证

正式 `tests/grid-return-resize-regression.cjs` 覆盖不旋转的原位快速返回、原有离屏淡出、横屏可见区变矮后的最短位移、变高后不移动、首行留白、过期可见比例、未挂载目标、布局延迟不重复校正、连续尺寸变化、挂载时再旋转、取消返回及浏览到另一张图后的文件定位。`tests/media-return-regression.cjs` 从原临时媒体返回回归移入正式测试，并覆盖列表、瀑布流、搜索、音频、取消及无晚到滚动。

调试构建以及两项返回测试、网格几何、缩略图原生更新、两张预取回归均通过。平板普通返回前后目标矩形同为 `[386,616][572,802]`，日志确认 `target=true`，请求阶段约 12 ms；这是单次行为检查，不是帧率基准。用户手动完成“竖屏网格靠底部打开 → 横屏返回”，反馈目标以最小滚动距离完整露出并飞回。

构建、原生日志和临时布局位于忽略的 `temp/rotation-return/`。未修改 NAS 文件。窗口尺寸模拟命令在该设备受限，没有修改系统调试配置；真实旋转由用户操作验证。用户确认正常后于 2026-10-25 要求提交源码，版本号不变，临时包与采样材料不纳入提交。
