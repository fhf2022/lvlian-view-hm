## 1.0.8 通知授权修复（2026-10-10）

用户反馈上传中没有保护通知。真机核对发现应用通知总开关为关闭、实况通知渠道为开启；1.0.7 仅以长时任务申请及 publish 返回成功判断可用，缺少通知授权检查，可能产生“后台任务已申请，但用户看不到通知”的状态。

EntryAbility 在 loadContent 成功后调用官方 `notificationManager.requestEnableNotification(context)`：先查询已有授权，未授权时首次请求；以独立 Preferences 记录首次决策，并合并启动与上传同时发生的请求。已授权不弹窗，拒绝后不重复弹窗，通过传输页的“开启通知”调用官方通知设置半模态页。传输开始/继续也共享该检查，授权返回后复核登录状态，避免弹窗期间切换账号导致旧任务运行。

申请 dataTransfer 前同时检查应用通知开关及 LIVE_VIEW 渠道。任一关闭时保留前台传输，切后台等待，界面显示具体原因；不再仅因 publish 成功就认为通知可见。通知授权不会替用户开启已关闭的渠道，仍由用户在官方设置中决定。

相册上传确认页已移除“上传时保持亮屏”，上传管理器也移除窗口亮屏控制；旧 SQLite 列保留以兼容任务记录，其值不再影响窗口。说明文字明确上传期间可在通知中心查看总进度，任务结束后通知随保护释放而收起。

主机回归覆盖首次请求去重、首次决策跨进程保留、拒绝与渠道关闭时的安全降级、官方设置返回后恢复保护；原有上传、下载保存、相册续传回归通过。官方依据：[请求通知授权](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/notification-enable)。

## 接入结果

`TransferBackgroundManager` 统一协调相册上传、普通上传和用户下载。只有队列可运行且网络/NAS 条件允许时申请 dataTransfer；使用 ContinuousTaskRequest 的独立任务 ID，视频播放也改为按自己的 ID 释放，避免互相停掉后台任务。系统通知使用 `NOTIFICATION_CONTENT_SYSTEM_LIVE_VIEW`、typeCode 8 和 downloadTemplate，由系统创建通知后更新其 ID，每秒至多发布一次。通知与应用传输页共享当前会话总进度，历史完成任务不计入。

保护及首次进度更新都成功后才允许后台继续。申请失败或通知更新失败保留前台操作，切后台后保留断点等待前台恢复；用户删除通知或系统取消保护时持久暂停队列，需用户继续。暂停、完成、退出登录、等待网络或 NAS 不可达时释放保护。下载在开始/继续时先取得系统下载目录授权，后台完成文件复制时复用本进程授权；未授权时不能在后台启动 Picker。

相册完成/跳过字节通过清单 RDB 聚合恢复，当前项并入完成汇总前清空其字节贡献，避免重复计数。未知大小不显示假百分比，失败项不显示全部成功。相册确认页默认不保持亮屏，说明保护开启后可切换应用或锁屏继续；点击进度通知进入传输页。

2026-10-09 真机使用独立 NAS 测试目录及 32 MiB 合成文件：后台相册上传完成；再次切后台后下载完成并落盘到公共下载目录；逐字节核对 33,554,432 字节一致。系统数据传输实况通知在锁屏界面可见。两个合成目录已移入回收站，合成源文件、公共下载文件和测试队列已清理；未上传用户相册。验证包使用独立上传数据库、下载 Preferences，最终交付包不包含测试入口。

主机回归执行生产 ArkTS：保护拒绝/通知失败降级、系统取消与迟到的通知回调竞争、独立视频任务 ID、Ability 销毁与重新创建、通知限频、混合方向字节加权、未知大小、失败上限、普通上传保护/无保护切后台及暂停续传、相册保护下后台完成、公共目录授权复用全部通过。原有上传、存储和相册回归通过，调试 HAP 构建成功。

最终 1.0.7（1000007）已覆盖安装到用户更新的 `192.168.0.142:44631`，保留应用数据。真机以通知相同的 Want 参数验证返回传输页成功；生产源码无探针引用及探针存储配置。最终调试 HAP SHA256：`14c25566e1d23e70f7dbff04c19667048ef29ae77972233b1522e9db0c7fcb6e`。

回归命令：`node tests/background-transfer-regression.cjs <typescript.js>`；原有 `upload-regression.cjs`、`storage-regression.cjs`、`album-upload-regression.cjs` 同样使用当前 DevEco SDK TypeScript 编译器。

## 结论及官方路线

现有相册上传、普通上传和用户主动下载均通过应用自己的 HttpTransport 发送请求，适合 Background Tasks Kit 的 `dataTransfer` 长时任务。这与把单个请求交给 `@ohos.request` 的系统托管上传下载不同，不需要先替换 NAS 分片上传及 Range 下载协议。

官方后台任务 API 示例提供了系统数据传输实况窗：申请长时任务后保存返回的 notificationId，用相同 ID 发布系统实况通知，typeCode 为 8，模板为 downloadTemplate，通过 progressValue 更新进度。这一路线由系统创建通知、应用更新，并非应用任意创建独立 Live View Kit 实况窗。因此显示标准传输总进度可先接该路线，无需先走独立 Live View Kit 服务权益申请。呈现位置、胶囊及锁屏具体样式依系统能力，需真机验证，不承诺任意自定义布局。

项目已声明 `ohos.permission.KEEP_BACKGROUND_RUNNING`；需为 EntryAbility 添加 dataTransfer 后台模式，并更新后台用途说明。DATA_TRANSFER 本身不需要特殊场景/计算任务使用的 `KEEP_BACKGROUND_RUNNING_SYSTEM` ACL；本次新取得的 READ_IMAGEVIDEO 发布 Profile 继续承担图库读取授权，与后台任务权限是不同用途。

DATA_TRANSFER 必须报告真实传输进度。官方说明首次进度长时间超过十分钟未更新可取消任务，并提供低传输速率、用户删除通知等取消原因。不能通过发布虚假进度维持无实际传输的保活。用户暂停、全部结束、等待 Wi-Fi、NAS 不可达时应保存任务并释放对应保护；系统取消时也应停止传输、保存断点。保护不是杀进程或重启后的自动执行保证。

## 接入设计

- AlbumUploadManager 的 runnable、错误处理和 finally 以 foreground 决定能否继续，Index 的前后台/页面生命周期也设置该状态。应拆分“界面可见”“上传任务允许运行”“系统保护已成功取得”，避免页面遮挡、切换页面或锁屏把传输任务误停。图库扫描、用户授权及相册选择在前台完成；后台原图读取另作真机验证。
- DownloadQueueManager 已有流式 HTTP、Range、持久 .part 和收到字节数，可复用。DownloadDestination 当前在完成时调用 DOWNLOAD 模式 Picker 获取目录；需核对后台目录授权和最终写入，必要时在前台开始任务时先取得目标权限，后台不得弹出需要交互的 Picker。保存失败保留完整暂存，显示等待保存，不能提前宣告下载成功。
- NasConnection 退后台会取消恢复计时，retryNow/schedule 也受 foreground 限制。接入后需明确受保护的传输是否持有恢复需求，避免无关页面/缩略图触发后台探测；长期 NAS 离线释放保护并保留任务，回到前台或用户继续时恢复。
- VideoBackgroundTaskManager 当前使用列表版 startBackgroundRunning 和不带 ID 的 stopBackgroundRunning。同一 EntryAbility 的传输与视频不能各自争用或全局停止长时任务。API 26 支持 ContinuousTaskRequest / continuousTaskId，可改为任务 ID 分别管理，只停止自己持有的任务；覆盖“同时看视频和传输，先后关闭/暂停”的测试。
- 保护管理及通知发布由一个传输协调器持有，不依赖某一张任务卡、页面刷新或 UI listener 存活。多个任务共同使用传输总进度，不为每张照片申请一个长时任务。不把缩略图预取、浏览图片缓存算入用户后台传输批次。

## 总进度口径

上传相册清单已固定成员和每项 size，job.bytes 是清单总大小；当前仅持久保存完成/跳过/失败数量和当前文件进度，需补充可恢复的字节汇总。完成项、跳过项大小可在项目状态变化时用 RDB 聚合，不能每次进度刷新扫描整个相册。

相册处理总进度按字节加权：`（已成功项大小 + 已跳过项大小 + 当前仍在传输项的已确认字节）/ 清单总大小`。已跳过项代表无需再次上传的已处理内容，不计入实际传输速度。当前项完成并并入汇总后不能重复加 currentBytes。断点恢复以 NAS 实际确认的偏移为准；未获成功确认的块不算成功完成。失败项单独显示，全部处理结束但有失败应显示“部分失败”，不能伪装为全部上传成功。

下载按批次总 size 与各项 receivedBytes 汇总，落盘完成前保留保存中状态。大小未知时显示已传输大小和数量，不造百分比。展示例如“上传相册 42% · 已处理 318/1322 张 · 跳过 85 张”；上传与下载同时运行时，卡片显示各方向数量，主进度汇总当前传输会话。加入新任务导致分母变化时明确更新批次范围，不能静默混入历史完成任务。

界面与系统通知复用同一份聚合快照，建议约每秒最多一次进度通知，状态变化及时更新。速度、预计剩余时间只根据实际传输量估算。暂停、失败、系统取消、退出登录、账号变更分别处理，通知不泄露照片文件名等私有内容。

## 交互与验证

允许后台传输后，确认页改为明确说明可切换应用/锁屏继续，保持 Wi-Fi 限制；保持亮屏可选，不作为后台能力的必要条件。点击系统进度通知进入传输页，暂停与继续沿用原队列语义。保护申请或通知更新失败时仍允许前台传输，退后台安全暂停并给出原因，避免显示“已后台保护”但实际冻结。

真机至少验证：相册上传和下载分别锁屏/切后台、混合上传下载、同时视频播放、总进度与重复跳过、暂停续传、网络切换、NAS 关机、删除系统通知、退出登录、进程被终止后恢复，以及下载目录落盘。上传验证继续使用合成图片与独立 NAS 测试目录，不擅自上传用户大相册。

若后续需要更丰富的自定义服务实况窗，再申请 Live View Kit：AGC“项目设置 > 开放能力管理 > 实况窗服务”，提交场景及设计附件；联调后还需申请正式权限并重新生成包含原图库权限及实况权益的 Profile。权益是否开通由华为审核决定，标准数据传输实况窗不以该审批为前置。
