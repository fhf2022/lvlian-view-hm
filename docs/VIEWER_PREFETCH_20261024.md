# 大图两张预取测试版

本轮基于 `31edd84`。当前原图呈现、空闲约 200 ms 后，沿浏览方向预取后续两张原图文件；反向浏览时方向随之改变。固定窗口距离为 2，不补到第 3 张。已经缓存的文件直接跳过。

- 当前图和邻图共用 `ViewerPrefetchCoordinator` 的文件任务，非计费网络最多 2 个在途下载，计费网络新任务并发为 1，沿用自动原图开关；手动加载当前图仍可使用。
- 翻到正在预取的图片时，接管该文件任务并接收其进度，不重复打开同一 `.part`。身份使用原有账号、NAS 和文件版本缓存键。
- 窗口外及关闭后的任务取消；取消中的旧任务实际结束并关闭文件后才释放槽位。同一文件跨查看会话重新打开时，等待旧写入者释放后再启动。
- 文件下载与 PixelMap 解码分开。邻图只落盘；旧当前图完成下载后若已离开当前页，不再启动原图解码。原图解码期间翻页也不提交旧图，并交给原有清理逻辑回收。
- HTTP 流式传输增加可选取消信号，使没有收到新数据的在途请求也能销毁；未传该参数的其他下载继续使用原接口。保留原有强 ETag、If-Range、完整性检查和账号隔离。
- 预取失败在当前窗口不立即循环重试；换页或主动加载当前图时可再次尝试。触摸期间不启动新预取，已有窗口内下载继续，元数据回调避开交互繁忙期。

## 已验证与待验证

`tests/viewer-prefetch-regression.cjs` 覆盖两张同时启动、总并发、窗口边界、接管与进度、反向和跳转、计费网络与手动加载、失败不循环、取消中的同文件写入互斥、跨账号隔离，以及没有响应头/数据时的真实 HttpTransport 取消。原有 24 项传输审计回归、网格位置、图片属性更新和媒体返回回归通过；调试构建通过。
