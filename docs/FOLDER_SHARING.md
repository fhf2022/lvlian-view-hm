# 文件夹分享与隔空传送

适用版本：1.0.15。文件夹按原目录分享，不转为 ZIP，不更改 NAS 原文件。

## 使用

列表、网格中长按文件夹点击「分享」，或多选后点击底栏分享；可将文件夹与普通文件一起选中。瀑布流只显示图片，继续使用原有图片分享。

支持隔空传送的设备可对当前选择“一抓一放”。首次需要从 NAS 下载内容；约 5 秒内准备不完时，本次手势结束，应用继续准备并提示重新抓取。大文件夹推荐分享按钮，保持应用前台直到系统面板出现。系统功能是否可用由设备、系统设置及附近设备条件决定。

## 限制与存储

- 一次选择最多 500 项，递归最多 10,000 项、64 层。无文件的文件夹无法发送。
- 系统传送不会保留空目录。非空目录的层级、原文件名及内容保留；本机不区分大小写的同名冲突会提示拆分，避免覆盖。
- 需要可访问 NAS、读取权限和足够本机空间。文件夹内有文件未准备完成时停止整批，不发送残缺内容。准备期间账号或当前分享上下文失效会取消。
- 暂存在系统 DOWNLOAD 模式取得的本应用目录下：`Download/cn.fhf.linkfiles/temp/.linkfiles-folder-share-v1/<任务ID>/`。包含文件夹时整批使用同一位置，避免系统拒绝混合来源；纯文件继续走原缓存路径。
- 暂存计入缓存上限。系统接手回调不提供传输完成保证，故至少保留 24 小时；期间自动淘汰和普通清缓存不会删除这批文件。到期后在下一次文件夹分享或显式清缓存时回收，不承诺定时后台清理。
- 中断的准备任务通过私有日志恢复清理，仅删除记录属于本应用的文件和空目录，不递归清理用户的下载目录，也不删除主动下载保存的文件。

分享准备使用现有两并发缓存工人，下载后复制到公共暂存即可释放对应源缓存的分享占用。缓存不足会停止；原缓存和公共副本同时存在时会占用额外空间。没有新增权限、整文件内存拷贝、滚动期目录扫描或另一套下载器。

## 验证与依据

2026-11-01 手机、平板实测：私有缓存的目录 URI 被系统拒绝；改用公共用户目录 URI 后文件夹发送成功。混合批次统一公共来源后也成功。接收方检查了目录层级、中文名和不同目录中的同名合成文本。系统丢弃空目录已复现，未用占位文件伪造目录保留。

用户确认 DOWNLOAD 目录、文件描述符复制方案的“一抓一放”验证版传送成功；最终整合版实际检查系统分享入口和混合批次，未将原型手势结果写成最终版所有设备验收。

主机测试覆盖生产准备逻辑、两并发缓存、分页、路径校验、账号隔离、同名冲突、失败清理、空间限制、文件句柄关闭、重启日志和保留期。它们模拟系统授权，不代替真实分享服务。

官方接口参考：[DOWNLOAD 模式保存用户文件](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/save-user-file)、[系统分享 SharedRecord](https://developer.huawei.com/consumer/cn/doc/harmonyos-references/share-system-share)。公共目录通过现有 `DownloadDestination` 取得；记录使用 `general.folder` 和系统返回的用户文件 URI。
