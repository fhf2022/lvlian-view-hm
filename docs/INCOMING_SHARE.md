# 从系统分享上传

在系统文件管理器或其他应用中选择文件，点击分享并选择“联文件”（首次可能位于“全部”中）。登录后选择 NAS 目标文件夹，点击“上传 N 项到此处”；随后进入传输页的上传模式。支持单文件和多文件，同名文件跳过，后台保护、网络策略、暂停与续传均沿用普通上传。

位置选择直接复用复制／移动的 `TaskPanel` 和按层目录列表，当前支持“我的云盘”目录。取消或系统返回不会上传。首次使用仍先完成开屏隐私同意；未登录时保留本次请求，登录后再选择位置。

接收流程在 `EntryAbility` 的 `onCreate`／`onNewWant` 中调用官方 `systemShare.getSharedData`，由 `IncomingShareManager` 顺序保留请求。仅处理带 `file://` URI 的文件记录，去除相同 URI；纯文本、网页链接和文件夹不能作为文件上传。UTD 的物理文件与逻辑内容有不同继承根，因此同时声明 `general.file` 和 `general.object`，覆盖媒体、文档、压缩包及普通文件。每批最多 500 个记录，与 Share Kit 上限一致；来源应用仍可能有更低限制。

只有确认目标后才由既有 `UploadQueueManager` 有界分块暂存，成功暂存后无需再依赖来源应用的临时 URI 授权。未确认请求只放在内存；进程被终止后需重新分享。来源不提供文件、云文件未下载或授权失效时，无法绕过来源应用的限制，用户需在来源应用准备好文件再分享。没有新增权限，没有访问任意系统路径，也不会把 URL 当作下载任务。

目标选择时记录 NAS 账号作用域，确认及每个文件导入时再校验；不会用旧账号选定的位置向新账号上传。连续分享按顺序处理，已有选择不会被新请求覆盖。解析失败有提示，单项读取失败不阻止其他项；已生成的失败任务仍可在原传输界面查看。

回归脚本与合成测试材料位于忽略目录 `temp/share-receive/`；原上传队列回归为 `tests/upload-regression.cjs`。测试入口仅存在临时验证包，交付包不包含生成文件或触发分享的调试分支。

任务行通过 `TransferQueueTaskRow` 的 `@ObjectLink` 直接观察任务，视觉仍复用 `TransferTaskListRow`。上传队列恢复持久化记录时重新构造可观察实例，下载快照和上传恢复共用 `DownloadTaskRecord.copyInto`。避免按值 Builder 冻结行参数，也不通过不断更换列表 key 强制重建进度行。

## 从联文件拖出所选文件

文件管理的多选模式中，按住已选文件，保持按住等待原文件准备好后拖到其他应用。短时间内移动仍走原有范围反选，不改变首末节点间的反转规则。列表、网格和瀑布流使用同一导出路径。

导出使用系统 `executeDrag` 和 UDMF 文件 URI，沿用分享的账号隔离缓存、网络限制和最多两个缓存工作槽；不以缩略图充当原文件。每批最多 500 个文件，包含文件夹时提示重新选择，不擅自少传。松手、离开多选或切换账号会使未完成的准备失效，原文件保留在现有缓存中；取消请求实际退出前不提前归还准备槽。缓存与预览位图在原生拖拽结束后释放持有。

`tests/file-export-regression.cjs` 检查原文件记录、名称元数据、预览尺寸、有界并发、取消与资源持有及范围反选分流。平板以 temp 中的合成文本和 ZIP 验证系统拖拽启动、数量和取消后选中状态；分屏拖至系统文件管理后生成两个文件，总大小 252 B 与来源一致。系统文件管理采用 URI 的缓存文件名，仍会带缓存前缀；UDMF 已提供原名称元数据，但不保证接收应用使用该字段。未把该项记录视为所有第三方应用均能接收的兼容性结论。
