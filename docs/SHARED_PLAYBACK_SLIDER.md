# 公共播放滑杆

HarmonyCast 与联文件使用相同的 `entry/src/main/ets/shared/PlaybackSlider.ets`。主源码在 HarmonyCast，联文件保存同步副本；两个仓库可以分别克隆、构建，不依赖另一个工程的本地绝对路径，也不引入播放器或网络实现。

公共组件负责原生 Slider 输入、横竖轨道、可选缓存层、圆球、点按动画与取消清理。点按按下即预览，松手提交一次；160 ms 动画完成后隐藏圆球，连点从当前显示位置接续，拖动立即跟手。动画只更新绘制，不发送播放指令。视频缓存层必须显式传入，倍速和音量不绘制缓存。

`remote/RemoteSlider.ets` 仅适配 HarmonyCast 的 V1 参数和回调；联文件的 `components/VideoControlSlider.ets` 仅适配 V2 回调。组件间传递基本类型，适用于当前 API 24 及以上基线。原有倍速换算、播放器确认、SOAP、音量合并发送、安全区和页面状态由各自项目负责。

## 同步修改

修改 HarmonyCast 中的公共组件，在该仓库运行：

```powershell
node scripts/sync-playback-slider.cjs --write "D:/code/harmony/ugreenlink-remote"
node scripts/sync-playback-slider.cjs --check "D:/code/harmony/ugreenlink-remote"
```

路径只是命令示例，传入另一仓库的实际位置。联文件也可以运行 `--check`，但禁止从副本反向 `--write` 覆盖主源码。同步只写公共组件与同步脚本；校验只读，发现差异返回非零退出码，并按统一换行计算 SHA256。

改动后分别构建两个工程，检查接收端进度与倍速、遥控端进度与倍速、竖向音量，以及联文件进度与倍速。重点检查快速松手、连续点按、拖动中断动画、取消与返回、横竖屏变化、缓存轨道和旧回调。不要在适配层重新增加绘制、手势或计时器；新交互应修改公共源码并同步。

## 本轮验证

两个工程的 debug 签名构建及覆盖安装均通过；源码与同步脚本的一致性校验通过。共享回归执行实际输入回调与适配层，覆盖旧值覆盖、重复提交、取消尾事件、松手完成动效、连点旧回调、拖动无逐帧动画、几何变更及退出重建，并验证同步工具只读检测差异、主仓写入和误反向覆盖保护。

HarmonyCast 的 101 项既有播放器、遥控布局、材质和画面手势回归通过；API 26 手机的接收播放页验证 0.25×／4×／恢复 1× 及暂停时点按跳转。用户已确认本轮真机效果。API 24 本轮未另做真机复测。临时测试脚本及结果在联文件 `temp/slider-tap/`，构建与既有回归日志在各工程的 `temp/` 或 `.test/`。
