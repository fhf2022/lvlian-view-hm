# 玻璃控件统一约束

2026-10-23，设计与迁移约束；本文件不代表已经完成界面改造或平板验收。

目标是统一手机、平板和不同页面的视觉尺寸与交互规则，同时保留已验证的原生形变、阴影、返回动画和触摸行为。统一不意味着将所有控件改成同一种 Tabs 或 Navigation。

## 三种边界分别计算

1. **控件本体**：按钮、胶囊、时间轴实际的排版尺寸；按 vp 定义，不按屏幕宽度等比放大。
2. **效果承载范围**：为系统材质形变、位移、阴影和高光预留的渲染空间；可以大于本体，但不能据此放大按钮和文字。
3. **交互范围**：实际按钮／轨道／日期标签的触摸区域；透明效果留白不得拦住文件列表。按压后拖动的完整事件序列仍由原控件持有。

内容区底部避让依据本体位置、安全区和可读留白计算；不能直接使用大号材质宿主高度。渲染留白、点击扩展和内容避让也不能复用同一个 padding 值。

## 已验证基线必须保留

| 控件 | 当前几何和宿主 | 迁移时不能丢失的约束 |
| --- | --- | --- |
| 首页／多选／文件工具栏 | 56vp 本体，底部 Tabs 提供材质作用域；宿主另有 20vp 上方效果空间和 40vp 布局补偿 | 保留现有真实渲染空间、底部对齐和透明间隙触摸路由；不能将整个宿主缩至 56vp |
| 图片查看底栏 | 56vp 原生悬浮 TabBar；自定义内容高 48vp，适配上下各 4vp 的系统留白 | 48vp 不是外壳高度不一致的证据；更换宿主前须实测内容、材质和触摸矩形，不能机械替换数值 |
| 玻璃时间轴 | 42vp 轨道、68vp 宿主宽；轨道上下各留 16vp，动态高度上限 520vp | 保留上下效果空间、顶部位置和底栏间距；刻度内容可裁剪，材质外层不能同样裁剪 |
| 时间轴日期标签 | 当前是与轨道重叠的普通主题色标签，58×30vp | 不在重叠位置叠加第二层折射材质；触摸归时间轴，避免重复选中和展开 |
| 悬浮导入球／展开菜单 | 56vp 球；Navigation 标题作用域负责材质，独立精确尺寸层负责操作 | 保留可绘制阴影的宿主范围；视觉层和交互层必须使用同一套位置／展开几何 |

底栏 20vp 上方空间来自 `06c3731`；透明间隙与悬浮球触摸路由来自 `2465154`。媒体返回时保留宿主的要求见 [PARENT_CHROME_RETENTION.md](PARENT_CHROME_RETENTION.md)。这些是需要回归保护的行为，不是可以直接删除的冗余包装。

时间轴收起时只露出日期标签的一部分是现有交互设计；这和展开态的轨道／阴影被意外截断不同，不能一律移除裁剪或平移。

## 统一边界

- **尺寸规范**：普通底栏本体 56vp、图标 24vp、默认文字 12fp；首页、多选和图片操作栏的常规胶囊宽度沿用 328vp，窄窗口按可用宽度收缩。文件工具组使用相同宽度约束，内部圆钮和排序胶囊保持各自尺寸。不同按钮数量仍需检查文字和触摸宽度，不通过整体缩放适配。
- **时间轴规范**：轨道宽度、日期标签、刻度字号和效果留白跨设备保持同一逻辑尺寸；仅轨道长度随可用高度变化，沿用当前上限与小窗口隐藏规则。
- **材质规范**：集中定义材质参数，但按宿主保留稳定实例，不能在 build 或拖动每帧创建。底栏沿用原生阴影；时间轴当前关闭原生阴影、使用单个自定义阴影，保持明确的阴影所有者，避免叠加两套阴影。
- **安全区**：只影响停靠位置和内容避让，不能改变按钮本体高度。横竖屏、分屏重新计算窗口可用范围，不用 phone／tablet 分支复制一套尺寸。
- **裁剪**：优先检查原生 TabBar／标题栏内部裁剪及其真实承载尺寸；`clip(false)` 不是充分修复。只在需要限制图片、文字或刻度内容时使用局部裁剪，不能连带切掉材质层。
- **交互**：可见控件接受输入，透明留白透传；隐藏或被覆盖的控件及其子节点都退出输入。保留现有图片返回时的提前解锁时序，避免再次吞掉首划。不能凭名称把 HitTestMode.None 和 BLOCK_DESCENDANTS 互换。
- **生命周期**：所属页面存在时保留宿主；媒体、菜单、搜索和多选的短期变化不触发无谓重建。显示、绘制、输入所有权分别管理，避免返回时材质重新加载或旧状态闪现。
- **光效**：材质、高光 Canvas 和操作区由同一份控件几何驱动。现在 ProximityLightReceiver 中重复的排序胶囊宽度等值应归入共享几何，不能因缩窄工具组让高光画到错误位置。

系统字体缩放、显示缩放及不同设备密度仍按平台规则处理；所谓跨设备尺寸一致指相同设置下的逻辑尺寸，不要求像素数一致，也不能用强制字号缩放限制掩盖布局问题。

## 代码组织与迁移顺序

1. 先记录本版手机与平板的静止／按压／拖动矩形和截图，将已验证几何作为基线。平板当前停在隐私托管错误页，底栏实际尺寸差异尚未测量，不能以推测替代测量。
2. 抽取纯几何与材质规则，保持已有数字、节点树和行为不变。共享函数只计算本体、效果范围、命中范围和安全区，不读取磁盘或网络。
3. 底部操作栏、时间轴和悬浮导入分别拥有小型适配组件，内部保留各自合适的 Tabs／Navigation。禁止做包含大量布尔开关、同时处理导航、多选、时间轴和导入业务的万能组件。
4. 在同类底栏中逐个迁移重复的框架和按钮排版；文件工具组的宽度、高光和命中范围一起迁移。业务页面只传动作与显示状态，不再自行叠加效果 padding 或补偿偏移。
5. 图片栏现有原生悬浮宿主只有在替代实现通过真实设备的形变、阴影和图片手势回归后才替换；必要的系统适配差异集中在适配组件内部并解释原因。
6. 每迁移一类即验收，再删除被替代的旧路径。保留一个布局来源，不长期并存新旧实现和设备专用补丁；不同时重构图片返回动画或文件加载管线。

## 合入验收

本机几何回归可验证窄屏、宽屏、横屏、分屏、安全区、效果范围与命中矩形；它不能证明原生材质没有裁剪。渲染变更还须在手机和平板验证：

- 底栏左、中、右按压及上下／左右拖动后回弹：按钮、高光、形变边缘、阴影均无硬切线。
- 底栏上方与各胶囊间透明区域可直接点击、滚动文件；悬浮球拖至右下角不穿透。
- 时间轴顶端、中部、底端按压和拖动，展开／收起、日期定位及离开日期标签均正确；不留下持续 scrub 状态阻止缩略图加载。
- 打开图片、音频、视频和菜单再返回，控件节点不无谓重建；图片返回首划有效。
- 横竖屏、分屏、亮暗主题、系统显示／文字缩放；最后一项文件可滚动至底栏上方。
- 返回及滚动期间检查材质实例和布局更新范围，没有因集中封装引入全屏逐帧重建。

真实设备有任何裁剪、死区或返回回归时，保留原宿主，不用“构建通过”宣称玻璃控件迁移通过。

## 官方依据

通过 DevEco CLI 核对：

- `@ohos.arkui.uiMaterial (系统材质)`：ImmersiveMaterial 仅在支持的标题栏、底部 TabBar 和弹层等作用域生效，不能任意移至普通容器。
- [沉浸式系统材质视效](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-immersive-light-sense-common-capability)：interactive 提供按压弹性形变；原生 applyShadow 阴影优先于通用 shadow，自定义阴影需先关闭原生阴影。

预留 20vp／16vp 等具体数字来自本项目历史修复，不是官方承诺的最大形变幅度；不能据此宣称已覆盖所有设备。
