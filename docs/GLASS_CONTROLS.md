# 玻璃控件统一约束

2026-10-23，设计约束与本轮实现记录；设备验证范围见文末。

目标是统一手机、平板和不同页面的视觉尺寸与交互规则，同时保留已验证的原生形变、阴影、返回动画和触摸行为。统一不意味着将所有控件改成同一种 Tabs 或 Navigation。

## 三种边界分别计算

1. **控件本体**：按钮、胶囊、时间轴实际的排版尺寸；按 vp 定义，不按屏幕宽度等比放大。
2. **效果承载范围**：为系统材质形变、位移、阴影和高光预留的渲染空间；可以大于本体，但不能据此放大按钮和文字。
3. **交互范围**：实际按钮／轨道／日期标签的触摸区域；透明效果留白不得拦住文件列表。按压后拖动的完整事件序列仍由原控件持有。

内容区底部避让依据本体位置、安全区和可读留白计算；不能直接使用大号材质宿主高度。渲染留白、点击扩展和内容避让也不能复用同一个 padding 值。

## 改造前的基线必须保留

| 控件 | 当前几何和宿主 | 迁移时不能丢失的约束 |
| --- | --- | --- |
| 首页／多选／文件工具栏 | 56vp 本体，底部 Tabs 提供材质作用域；宿主另有 20vp 上方效果空间和 40vp 布局补偿 | 保留现有真实渲染空间、底部对齐和透明间隙触摸路由；不能将整个宿主缩至 56vp |
| 图片查看底栏 | 56vp 原生悬浮 TabBar；自定义内容高 48vp，适配上下各 4vp 的系统留白 | 48vp 不是外壳高度不一致的证据；更换宿主前须实测内容、材质和触摸矩形，不能机械替换数值 |
| 玻璃时间轴 | 42vp 轨道、68vp 宿主宽；轨道上下各留 16vp，动态高度上限 520vp | 保留上下效果空间和底栏间距；顶部位置按下文的内容区居中规则计算；刻度内容可裁剪，材质外层不能同样裁剪 |
| 时间轴日期标签 | 当前是与轨道重叠的普通主题色标签，58×30vp | 不在重叠位置叠加第二层折射材质；触摸归时间轴，避免重复选中和展开 |
| 悬浮导入球／展开菜单 | 56vp 球；Navigation 标题作用域负责材质，独立精确尺寸层负责操作 | 保留可绘制阴影的宿主范围；视觉层和交互层必须使用同一套位置／展开几何 |

底栏 20vp 上方空间来自 `06c3731`；透明间隙与悬浮球触摸路由来自 `2465154`。媒体返回时保留宿主的要求见 [PARENT_CHROME_RETENTION.md](PARENT_CHROME_RETENTION.md)。这些是需要回归保护的行为，不是可以直接删除的冗余包装。

时间轴收起时只露出日期标签的一部分是现有交互设计；这和展开态的轨道／阴影被意外截断不同，不能一律移除裁剪或平移。

## 统一边界

- **尺寸规范**：普通底栏本体 56vp、图标 24vp、默认文字 12fp；首页、多选和图片操作栏的常规胶囊宽度沿用 328vp，窄窗口按可用宽度收缩。按用户明确要求，文件工具栏继续铺满窗口，保持左右圆钮、中间排序的分散布局；圆钮 56vp、排序胶囊 140×56vp，不收窄整个工具组。不同按钮数量仍需检查文字和触摸宽度，不通过整体缩放适配。
- **时间轴规范**：轨道宽度、日期标签、刻度字号和效果留白跨设备保持同一逻辑尺寸；轨道长度随可用高度变化，沿用当前上限与小窗口隐藏规则。包括上下效果空间的整个宿主，在文件顶栏下缘至悬浮底栏本体上缘之间垂直居中，两端各保留 8vp 间距；不再固定从顶栏下方开始排。
- **材质规范**：集中定义材质参数，但按宿主保留稳定实例，不能在 build 或拖动每帧创建。底栏沿用原生阴影；时间轴当前关闭原生阴影、使用单个自定义阴影，保持明确的阴影所有者，避免叠加两套阴影。
- **安全区**：只影响停靠位置和内容避让，不能改变按钮本体高度。横竖屏、分屏重新计算窗口可用范围，不用 phone／tablet 分支复制一套尺寸。
- **裁剪**：优先检查原生 TabBar／标题栏内部裁剪及其真实承载尺寸；`clip(false)` 不是充分修复。只在需要限制图片、文字或刻度内容时使用局部裁剪，不能连带切掉材质层。
- **交互**：可见控件接受输入，透明留白透传；隐藏或被覆盖的控件及其子节点都退出输入。保留现有图片返回时的提前解锁时序，避免再次吞掉首划。不能凭名称把 HitTestMode.None 和 BLOCK_DESCENDANTS 互换。
- **生命周期**：所属页面存在时保留宿主；媒体、菜单、搜索和多选的短期变化不触发无谓重建。显示、绘制、输入所有权分别管理，避免返回时材质重新加载或旧状态闪现。
- **光效**：材质、高光 Canvas 和操作区由同一份控件几何驱动。ProximityLightReceiver 中的排序胶囊宽度和工具栏边距归入共享几何，避免控件与高光使用不同尺寸。

系统字体缩放、显示缩放及不同设备密度仍按平台规则处理；所谓跨设备尺寸一致指相同设置下的逻辑尺寸，不要求像素数一致，也不能用强制字号缩放限制掩盖布局问题。

## 代码组织与迁移顺序

1. 先记录本版手机与平板的静止／按压／拖动矩形和截图，将已验证几何作为基线。平板已能进入应用，测到原生悬浮图片底栏约 755×130px，主页为 656×112px；不能只根据源代码中的 48vp 推断原因。
2. 抽取纯几何与材质规则，保持已有数字、节点树和行为不变。共享函数只计算本体、效果范围、命中范围和安全区，不读取磁盘或网络。
3. 底部操作栏、时间轴和悬浮导入分别拥有小型适配组件，内部保留各自合适的 Tabs／Navigation。禁止做包含大量布尔开关、同时处理导航、多选、时间轴和导入业务的万能组件。
4. 在同类底栏中逐个迁移重复的框架和按钮排版；文件工具组保持全宽分散布局，高光和命中范围继续对齐原控件。业务页面只传动作与显示状态，不再自行叠加效果 padding 或补偿偏移。
5. 图片栏现有原生悬浮宿主只有在替代实现通过真实设备的形变、阴影和图片手势回归后才替换；必要的系统适配差异集中在适配组件内部并解释原因。
6. 每迁移一类即验收，再删除被替代的旧路径。保留一个布局来源，不长期并存新旧实现和设备专用补丁；不同时重构图片返回动画或文件加载管线。

## 合入验收

本机几何回归可验证窄屏、宽屏、横屏、分屏、安全区、效果范围与命中矩形；它不能证明原生材质没有裁剪。渲染变更还须在手机和平板验证：

- 底栏左、中、右按压及上下／左右拖动后回弹：按钮、高光、形变边缘、阴影均无硬切线。
- 底栏上方与各胶囊间透明区域可直接点击、滚动文件；悬浮球拖至右下角不穿透。
- 时间轴顶端、中部、底端按压和拖动，展开／收起、日期定位及离开日期标签均正确；不留下持续 scrub 状态阻止缩略图加载。
- 打开图片、音频、视频和菜单再返回，控件节点不无谓重建；图片返回首划有效。
- 横竖屏、分屏、亮暗主题、系统显示／文字缩放；最后一项文件可滚动至底栏上方。
- 返回及滚动期间检查材质实例和布局更新范围，没有因集中封装引入全屏逐帧重建。

真实设备有任何裁剪、死区或返回回归时，保留原宿主，不用“构建通过”宣称玻璃控件迁移通过。

## 本轮实现与实测

- 改造前代码已提交并推送至 GitHub：`55fde68`。
- `GlassControlGeometry` 集中本体、效果留白、时间轴及导入菜单几何；`GlassMaterial` 集中材质参数，并由组件持有稳定实例。导入球不再每次重绘创建材质。
- `GlassBarHost` 为首页、多选、文件工具和图片操作栏提供同一个底部 Tabs 材质作用域。保留 156vp 宿主、116vp 页签槽、20vp 上方效果留白和 40vp 补偿，控件本体仍为 56vp，透明区域的根触摸路由未删除。
- 图片操作栏移除原来会在本机放大的 `barFloatingStyle` 路径，使用与首页相同的自定义材质表面。随之移除旧原生悬浮栏的 48vp 内容补偿、硬编码命中矩形，以及只写不读的查看器底栏宽度状态。
- 时间轴仍使用原 Tabs 宿主、轨道内部裁剪、独立日期标签和自定义阴影；仅共享几何与材质。悬浮球仍使用原 Navigation 视觉作用域与独立交互层。
- 文件工具栏按用户要求保留全宽分散布局。ProximityLightReceiver 与工具栏使用同一个排序宽度和边距来源。

### 时间轴位置补修

原布局以顶栏下方为固定起点，轨道达到 520vp 上限后，多出的可用高度全部留在下方，导致平板时间轴偏上。现在由 `GlassControlGeometry.timelineTop()` 按实际内容区计算宿主位置，与轨道高度计算共用顶栏下缘、底栏上缘及效果留白；窗口变化时按同一规则重新排布，没有增加设备类型分支。

同一台平板、同一窗口设置下，展开态宿主从 `[2728,198][2864,1302]` 移至 `[2728,439][2864,1543]`，纵向中心与内容区中心对齐；收起态为 `[2808,439][2880,1543]`。轨道长度、上下形变空间及横向收起距离不变。

补修后构建、覆盖安装、几何边界与原时间轴回归通过；平板已复查上／中／下段拖动、展开／收起和收起后立即滚动网格，宿主节点保持不变。截图与脚本在 `temp/audit-fixes/timeline-position-*`。本次没有新增手机、旋转或分屏实测。

### 轻菜单与文件详情统一

用户确认合并图片／音乐／文件详情、三处轻菜单外壳；另行确认合并两处“更多”的菜单行，以及按菜单分组清理滑选记录。

- 排序、多选“更多”、图片“更多”共用 `GlassMenuSurface`、`floatingMenuOptions()` 和稳定的 `GlassMaterial.overlay()` 实例。薄材质与底栏保持同一系列，文字使用支持反色的系统资源；排序文字原来的自定义主题色改为 `sys.color.font_primary`。材质及阴影只由原生 Popup 外壳绘制。没有将每行包成独立玻璃，也没有为了作用域套入底栏 Tabs。
- 两处“更多”共用 `GlassMenuRow`：文字、图标、分隔线、按压和触摸回调只有一份布局。页面仍提供自己的操作与滑选分组；多选的小型适配方法只负责选项执行前关闭菜单，不是第二套行布局。原图片展开转场保留。
- `clearSlideItems()` 只清除指定菜单的命中记录。两处“更多”在打开／关闭时清理各自分组；长按菜单仍在原来的原生退出完成时清理 `ctxmenu`，不改变预览卡、返回动画或底栏输入。
- 三处详情统一走 `showEntryDetails()`，图片的独立 Sheet、状态、布局和关闭分支已删除。继续使用原生居中 Dialog、模态遮罩和系统返回，宽屏宽度上限为原先的 400vp；不使用按设备类型划分的偏移补丁。
- 实测发现 `showDialog()` 生成的默认文字在薄材质下没有随背景反色，因此详情共用 `EntryDetailsContent`，显式使用系统文字色资源，由 `openCustomDialog()` 提供原生窗口和材质。只保留“确定”，长内容由受限高度的 Scroll 承载。没有为图片再造一套弹窗。
- `showTrackedDialog()` 同时跟踪普通原生对话框和上述详情呈现任务；打开失败及原生消失后均释放计数。确认早于窗口 ID 返回时延后关闭，重复确认只处理一次。图片横划、下拉及接续沿用这个已有模态计数，避免新增图片详情专属布尔状态。
