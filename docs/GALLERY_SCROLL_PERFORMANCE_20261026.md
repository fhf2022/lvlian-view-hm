# 平板图片网格滑动：实际刷新与系统图库对照（2026-10-26）

后续已接入完整交互的原生按行缓存，当前状态见 [接入与验收（2026-10-27）](GALLERY_ROW_CACHE_INTEGRATION_20261027.md)。下文保留前一轮撤回试验的原始记录。

后续已按用户要求改做等密度和资源路径的受控排查，见 [渲染差距原因记录](GALLERY_RENDERING_ROOT_CAUSE_20261026.md)。最新的整行绘制隔离原型在保留十列与原材质的前提下测到约 119 次刷新/秒，但尚未接入完整单图交互，不能作为正式版本成绩。本文早期系统图库数据对应带侧栏的月视图；不能直接与联文件十列逐张图片的网格比较实现效率。后续 Repeat 候选亦已暂存，生产代码最终恢复基线。

本轮只研究图片网格上下滑动。基线为 `eb029e7`，设备为 PCE-W30，HarmonyOS API 26、2880×1920、120 Hz。结论是：主线程耗时降低仍不足以说明画面已流畅；本轮没有得到兼顾原外观与快速滑动的稳定改善，所有生产代码试验均已撤回，平板恢复已存档的基线包。未保留新的缓存、材质或组件复用实现。

## 必须保留的界面

用户在本轮再次明确，系统图库也是渐变模糊背景与沉浸光感悬浮按钮的设计。联文件继续使用已有共用顶栏：

- 顶部背景为原有标准渐变模糊，向内容区自然过渡。
- 返回、多选、搜索保持各自的沉浸光感悬浮组件效果；保留尺寸、位置、柔体和阴影空间。
- 不使用一整块均匀模糊底板，不把按钮替换为普通透明或填色按钮，不为图库新增另一套顶栏。
- 不关闭系统按设备能力自动调整材质效果的机制。运行时测得当前设备的材质档位为 GENTLE；这不代表多个材质区域没有渲染成本。

这次撤回包括共享矩形顶栏材质、HDS Navigation 原型和单元格 `renderGroup` 缓存。先前约 103 / 99 次每秒的慢、中速结果属于已撤回的顶栏试验，不能归给保留原外观的版本。

## 评价方法

通过 SmartPerf `SP_daemon -f` 采集应用刷新次数及 `fpsJitters`。三档手势速度为 1600 / 3200 / 6400 px/s，每次手指移动 1400 px，三次向前、三次回滑循环，间隔 0.05 秒。每档采集 15 个窗口，去掉首个窗口，统计其余 14 个窗口。测量期间不截图、不查布局、不并行采集 trace 或内存。

这些值是应用 Surface 的刷新统计，不保证等于面板上逐帧成功呈现的 FPS。`fpsJitters` 用于观察刷新间隔；UI 线程 `OnVsyncEvent` 的工作耗时单独分析，不能用 `1000 / UI 耗时` 换算 FPS。120 Hz 单帧预算约 8.33 ms。

另一次独立 hitrace 采样使用六次完整手势、手势间隔 1 秒，区分 UI 工作和 Render Service 的渲染工作。与连续滑动的 SmartPerf 采样不是同一段运行，不能逐帧对应。

## 实测结果

联文件使用 Camera 目录，横屏 10 列；系统图库使用用户预先打开的大量图片界面，约 16～17 列。两者素材、缩略图来源和布局密度不同，不能当作严格相同内容的 A/B，也未分析系统图库的闭源源码。

| 手势速度 | 联文件基线平均刷新次数/秒 | 基线刷新间隔 P95 | 系统图库平均刷新次数/秒 | 图库刷新间隔 P95 |
| --- | ---: | ---: | ---: | ---: |
| 1600 px/s | 73.43 | 16.72 ms | 118.21 | 8.35 ms |
| 3200 px/s | 74.00 | 16.73 ms | 119.29 | 8.36 ms |
| 6400 px/s | 69.07 | 16.71 ms | 119.29 | 8.35 ms |

末尾重新安装同一基线包复测，慢速为 76.50、高速为 63.79 次/秒，高速 P95 为 24.97 ms。说明连续实验中的内容、缓存和设备状态存在明显波动；不能仅凭一次均值高几帧就保留改动。

独立 trace 中，基线 UI 工作 P95 约 8.83 ms，系统图库约 4.11 ms。新建一行十个单元时，基线 `BuildLazyItem` 累计约 4.6～6 ms，还会叠加布局与更新。Render Service 的 `RenderFrame` P95 基线约 15.25 ms、系统图库约 7.85 ms。这表明瓶颈同时包含新单元创建和渲染服务，不能只针对网络下载或只看 UI 线程。

基线渲染中可见多个独立材质区域和渐变滤镜；系统图库的区域组织与绘制量不同。公开文档也提示大量小材质区域的重复开销，但这只是定位依据，不是删掉用户指定外观的理由。

## 已撤回的方向

| 试验 | 观察 | 处理 |
| --- | --- | --- |
| 关闭材质、反色或高光 | 部分慢速样本有变化，快速滑动没有一致改善；关闭材质改变外观 | 全部撤回 |
| 共享顶栏材质、矩形底板、HDS 顶栏原型 | 部分样本提升，但渐变、悬浮按钮或安全区效果不符合要求 | 全部撤回 |
| 渐变区域绘制缓存 | 约 78.9 / 68.9 次每秒（慢 / 快），没有稳定收益 | 撤回 |
| Release 构建对照 | 约 75.6 / 66.2 次每秒（慢 / 快），调试包开销不足以解释差距 | 恢复调试验证基线 |
| 纯图片单元 `@Reusable` 原型 | 三档约 76.1 / 71.9 / 68.5，没有稳定收益；需要额外核对闭包和条目身份 | 撤回 |
| 原外观、单元格 `renderGroup(true)` | 三档约 84.9 / 81.2 / 67.2；高速 P95 24.95 ms，UI 工作 P95 10.56 ms、最大 38.72 ms | 撤回 |

最后一项慢、中速均值上升，但高速结果落在基线复测波动范围内，无法证明稳定提升；独立 trace 也没有支持更好的长帧表现。不能把它写成已经修好的优化，更不能宣称已证实每次都会退化。

泛化复用整个文件单元还会遇到编译后 Builder 捕获旧条目的风险，未作为可交付版本使用。没有增加全局图片缓存容量、缓存行数、强制刷新循环或在 Grid 上套用只适用于其他组件的高刷接口。

## 后续边界

下一项若继续试验，应保持原顶栏、底栏、时间轴、图片比例和下载策略不变，只减少新图片行创建时的无效节点及重复状态更新；先核对编译产物中的条目身份，再做三档实测。只有慢、中、快速的刷新与长帧都没有明显回退，并通过共享元素返回、首划、多选、搜索和旋转验证，才保留代码。不能再把材质关闭试验包装成外观不变的优化。

目前这些方向尚未形成通过上述条件的实现，滑动帧率问题仍未完全解决。此前已验证并存档的位置按需读取、稳定时间轴刻度及缩略图状态隔离仍保留，见 [2026-10-24 记录](GALLERY_SCROLL_PERFORMANCE_20261024.md)。
